Sales + Contracts dashboards

Full-resolution HTML, MJ light tokens, Explorer chrome. Click around — deal/contract clicks add an Explorer tab and toast the real NavigationService call. Nothing here is built yet.

What we found in code

Orders (the pattern): rail pages are jobs (dashboard, list, fulfillment). A record is NavigationService.OpenEntityRecord / OpenNewEntityRecord. The orders dashboard may switch views with mj-tab-nav, but it does not host open orders in a nested document strip. Header comment: “New/existing orders open as Explorer record tabs via NavigationService, not as rail pages.”

Sales (the antipattern): sales-nav.model.ts puts Workspace on the Deals rail. Dashboard and list rows call OpenDeal into mjs-deal-workspace, which keeps its own open-documents strip and inner panes. Nested tabs: Explorer → workspace strip → deal panes. Accounts correctly use OpenEntityRecord. The dashboard itself is four KPIs + a “closing soonest” table — the §9 queries (forecast by category, slippage, conversion, win rate, forecast history) already exist and are unused here.

Contracts: Marcelo did not repeat the workspace. Rails are dashboard / all contracts / renewals / awaiting / modifications. Grids use mj-explorer-entity-data-grid and OpenEntityRecord. The miss is the dashboard: five count pills and a manifesto card. Architecturally correct, operationally thin.

A · Pipeline command center recommended

Stacked Closed / Commit / Best Case / Pipeline (cumulative flags sliced for the bar). Waterfall from ForecastSnapshot. Stage conversion. Close-date buckets. Attention queues wired to Activity Sync. Inspect grid filters from every click. Deal click = Explorer tab, no workspace rail.

B · Living board as home

Kanban is the dashboard. Forecast is a ribbon. Cards show stall and last activity. Still OpenEntityRecord. Signed column is not a drop target — close from the form so the lock and contract policy run once.

C · Weekly motion

Monday briefing: won / lost / slipped / new + motion log + analyst. Thin as a working surface; board and list still required.

Files live in the contracts repo. Same chrome, no money.

A · Obligation command recommended

90-day notice/expiry calendar, four derived-column queues, hot list. Click = Explorer contract tab. Tiles and worklists cannot disagree.

B · Decision inbox

One ranked queue of verbs (attach paper, send notice, wait). Great for a single owner; weak portfolio shape.

C · Portfolio map

Company → counterparty → contract tree. Health is paper/notice. Slow for “what is due this week.”

I’d lean Sales A + Contracts A. Hybrids are fair: A’s inspect grid with B’s board as the rail page (not the home), C’s analyst as a side panel later. Do not keep the Workspace rail in any of them.
